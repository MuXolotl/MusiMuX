# VK Музыка API — руководство

Руководство по внутреннему API VK Музыки — закрытому интерфейсу, через который работают официальные клиенты (Android-приложение VK и VK Музыка, веб-раздел «Музыка»). Оно описывает полный доступ к музыкальному каталогу VK: медиатека пользователя, витрина рекомендаций, плейлисты, подкасты, тексты песен и навигация по разделам.

Этот API **не является публичным**. Публичный VK API (`v=5.x`) не является заменой внутренним музыкальным методам.
Для методов каталога и аудио текущий клиент по умолчанию использует внутреннюю
версию `8.154` и Android-заголовки; отдельные служебные/загрузочные вызовы
могут использовать другую версию (например, `5.143` для обложки плейлиста).

Документация сверена с текущей выборкой ответов и кодом Rust-клиента MusiMuX
(`crates/vkapi`). В ней агрегированы 1 762 JSON-ответа по 48 методам
(1 741 успешный и 21 с ошибкой); предыдущая выборка содержала 1 765 ответов
по 22 методам. Все 22 метода предыдущей выборки представлены и сейчас; набор
дополнен 26 именами, преимущественно write-, upload- и служебными вызовами.
Выборки неравномерны: текущая шире по методам, но содержит меньше ответов
`catalog.getSection`. Отсутствие поля или типа не доказывает удаление из API.
Идентификаторы, токены, пользовательские тексты и URL из ответов не публикуются;
примеры синтетические.

Параметры в тексте разделены по источнику: **манифесты** подтверждают только
имена параметров, записанные при конкретных захватах; **клиент MusiMuX** — то,
что формирует код, включая значения по умолчанию и дополнительные параметры.
Манифест не считается полным списком запроса.

Связанный документ: [`RESPONSE.md`](./RESPONSE.md) — справочник наблюдаемых
структур ответов и границ моделей Rust. В этом документе описаны вызовы API и
навигация по ответам.

> **Правовая рамка.** Документ описывает техническую сторону обмена и предназначен
> для клиентов, работающих с данными аккаунта, к которому выполнена авторизация.
> Внутренний API может меняться без предупреждения. Неизвестные поля и типы
> рекомендуется обрабатывать устойчиво: сохранять без потерь и не завершать разбор
> ошибкой.

## 1. Быстрый старт

Понадобится:

1. **`access_token`** с правами на музыку. Получается в результате авторизации клиента VK Музыки (через VK ID). Токен привязан к типу клиента; токены публичных standalone-приложений для музыкальных методов не подходят.
2. **Версия API `8.154` по умолчанию** — отдельные служебные вызовы могут её переопределять (§2.2, §4.7–4.8).
3. **Заголовки мобильного клиента** — см. §2.

Проверочный вызов (текущий пользователь и корневой каталог):

```bash
curl -X POST "https://api.vk.ru/method/users.get" \
  -H "User-Agent: VKAndroidApp/<version> (Android <version>; SDK <level>; <abi>; <manufacturer> <model>; <lang>; <width>x<height>)" \
  -H "X-VK-Android-Client: new" \
  --data-urlencode "access_token=<TOKEN>" \
  --data-urlencode "v=8.154" \
  --data-urlencode "device_id=<android_id:gcm_id>" \
  --data-urlencode "lang=ru"

curl -X POST "https://api.vk.ru/method/catalog.getAudio" \
  -H "User-Agent: VKAndroidApp/<version> (Android <version>; SDK <level>; <abi>; <manufacturer> <model>; <lang>; <width>x<height>)" \
  -H "X-VK-Android-Client: new" \
  --data-urlencode "access_token=<TOKEN>" \
  --data-urlencode "v=8.154" \
  --data-urlencode "device_id=<android_id:gcm_id>" \
  --data-urlencode "extended=1"
```

Первый вызов вернёт массив с объектом пользователя, второй — корневой конверт каталога с шестью разделами. Если вместо этого пришло `error.error_code = 8` — не прошла версия или заголовки (§2). Если `5` — токен не подходит (§1.1).

### 1.1. Про токены и сессию

- Срок токена ограничен: ошибки `1114`/`1117` означают, что сессию надо продлевать (процесс продления зависит от способа авторизации клиента, к музыкальному API отношения не имеет).
- Сервисные вызовы параметров запуска (`apps.getAppLaunchParams`) и сервисных токенов (`auth.getCredentialsForService`) для части типов токенов возвращают `100 (not integer)` — это не мешает работе с музыкой; такой ответ трактуется как «служба недоступна».

## 2. Транспорт: протокол, заголовки, версия

### 2.1. Эндпоинт и кодирование

Вызовы API-методов — `POST https://api.vk.ru/method/<имя.метода>` с телом
`application/x-www-form-urlencoded`. GET для этих методов не используется.
Файлы загружаются отдельно методом multipart на одноразовый адрес из
`upload_url` (§4.7–4.8).

### 2.2. Системные параметры каждого запроса

| Параметр | Значение | Назначение |
|---|---|---|
| `access_token` | токен сессии | Авторизация |
| `v` | по умолчанию `8.154` | Версия API; отдельные методы/загрузки могут явно переопределять её |
| `device_id` | `<android_id>:<gcm_id>` | Идентификатор устройства (GCM-формат) |
| `lang` | `ru` | Язык ответов |

### 2.3. HTTP-заголовки

Каждый запрос обязан воспроизводить окружение Android-приложения:

| Заголовок | Значение |
|---|---|
| `User-Agent` | `VKAndroidApp/<версия> (Android <версия>; SDK <уровень>; <abi>; <производитель> <модель>; ru; <ширина>x<высота>)` |
| `X-VK-Android-Client` | `new` |
| `Referer` | `https://id.vk.ru` |
| `Origin` | `https://id.vk.ru` |
| `Sec-Fetch-*`, `Accept` | стандартный набор браузерных/клиентских заголовков |

### 2.4. Почему `8.154`

Музыкальные методы включаются серверной логикой по версии внутреннего клиента. С публичной версией `5.x`:
- `catalog.*` отвечает ошибкой `8` (invalid version),
- `audio.search`, `audio.get` и прочие возвращают пустые списки.

Без полного набора заголовков §2.3 сервер не выдаёт контент даже с правильной версией.

### 2.5. Оболочка ответа

Успех — всегда объект `response`:
```json
{ "response": { "<method-specific-fields>": "<method-specific-value>" } }
```
Ошибка — объект `error`:
```json
{
  "error": {
    "error_code": 104,
    "error_msg": "Not found"
  }
}
```

Тип содержимого `response` зависит от метода: объект, массив (`audio.getById`, `audio.getPopular`, `audio.getStreamMixAudios`, `users.get`) или число (`audio.getCount`, `stats.trackEvents`). Сводная таблица — в конце [`RESPONSE.md`](./RESPONSE.md).

### 2.6. Параметры: манифесты и клиент — разные источники

`VkClient` автоматически добавляет `access_token`, `device_id` и `v` (по
умолчанию `8.154`), поэтому этих ключей может не быть в манифесте. Ниже
параметры манифеста — только наблюдавшиеся **имена**, без значений. Правая
колонка — что дополнительно/всегда формирует текущий Rust-клиент.

| Метод | Ключи в текущих манифестах | Формирование в Rust-клиенте |
|---|---|---|
| `catalog.getAudio` | `extended`, `owner_id`, `url` | `extended=1`; `url` опционален. `owner_id` есть в захватах, но не передаётся этим методом MusiMuX |
| `catalog.getSection` | `extended`, `need_blocks`, `section_id`, `start_from` | Всегда `extended=1`, `need_blocks=1`; курсор только при продолжении |
| `catalog.getBlockItems` | `block_id`, `start_from` | `extended=1` формируется кодом, но в текущих манифестах не записан |
| `catalog.getAudioArtist` | `artist_id` | Код добавляет `extended=1` |
| `catalog.getAudioCurator` | `curator_id`, `url` | Код добавляет `extended=1` |
| `catalog.getAudioSearch` | `context`, `extended`, `need_blocks`, `query` | `extended=1`; пустой запрос — `need_blocks=1`, выдача — `query` (`context` опционален), живые подсказки — `query`, `need_blocks=1`, `show_suggests=1` (в текущих манифестах `show_suggests` не записан) |
| `audio.get` | `access_key`, `album_id`, `count`, `extended`, `offset`, `owner_id`, `playlist_id` | Код всегда добавляет `extended=1`; `playlist_id`/`access_key` используются в варианте чтения плейлиста |
| `audio.getRecommendations` | `count`, `target_audio` | Код дополнительно отправляет `offset`; он не попал в текущие манифесты |
| `audio.getPopular` | `count`, `only_eng` | Код также отправляет `offset` |
| `audio.getPlaylistById` | `access_key`, `audio_count`, `extended`, `owner_id`, `playlist_id` | Код всегда отправляет `extended=1`; `audio_count` присутствует в захвате, но не формируется текущим методом MusiMuX |
| `audio.search` | `count`, `extended`, `offset`, `q`, `search_own`, `sort` | Код отправляет `extended=1`, `sort=0`; `search_own=1` — только для поиска в своей медиатеке |
| `audio.getStreamMixAudios` | `append`, `count`, `mix_id` | Код поддерживает необязательные `options` и `entity_id`; в текущем наборе они не наблюдались |

`catalog.replaceBlocks` и три шага загрузки, отмеченные в §4.7–4.8, есть в
захватах/инструментах, но не все из них вызываются обычным UI-клиентом.

## 3. Модель каталога

Понимание этого раздела обязательно: витрина VK Музыки живёт не в `audio.*`, а в `catalog.*`, и построена иначе, чем типичные REST-ресурсы.

### 3.1. Скелет и сущности

Ответ каталожного метода («конверт») состоит из двух частей:

1. **Скелет**: секция → упорядоченный массив `blocks`. Блок — отображаемый ряд (карусель, список, заголовок, разделитель, кнопки). Блок знает *как* рисоваться (`layout`) и *что* показывать (`data_type`), но содержит не сами сущности, а списки их идентификаторов: `audios_ids`, `playlists_ids`, `links_ids` и т.д.
2. **Пакеты сущностей**: корневые ключи конверта `audios`, `playlists`, `links`, `audio_books`, … — массивы полных объектов.

Клиент обязан «разрешить» скелет: для каждого блока взять его `*_ids` и подставить объекты из пакетов **в том же порядке**. Порядок идентификаторов — это порядок отрисовки VK, перемешивать его нельзя.

```json
{
  "audios": [ { "id": 0, "owner_id": 0, "title": "<track-title>" } ],
  "section": {
    "id": "<opaque-section-id>",
    "title": "<section-title>",
    "blocks": [
      {
        "id": "<opaque-block-id>",
        "data_type": "music_audios",
        "layout": { "name": "list" },
        "audios_ids": [ "0_0" ]
      }
    ]
  }
}
```

### 3.2. Четыре формы конверта

| Форма | Ключи верхнего уровня | Методы |
|---|---|---|
| Корневой каталог | `catalog { default_section, sections }` | `getAudio` без `url`, `getAudioSearch`, `getAudioArtist` |
| Детальная секция | `section` | `getSection`, `getAudio` с `url` |
| Одиночный блок | `block` | `getBlockItems` |
| Замены вкладок | `replacements { new_next_from, replacements[{ from_block_ids, to_blocks }] }` | `replaceBlocks` |

Плюс набор пакетов сущностей произвольного состава (пустой у корневого каталога).

### 3.3. Навигационный граф

Точка входа — `catalog.getAudio` без параметров: разделы-указатели («Главная», «Моя музыка», «Радио», «Обзор», «Книги и шоу», «Детям» и другие в зависимости от аккаунта — «Недавнее», «Подписки», жанровые подборки кураторов и прочие), блоков и пакетов в ответе нет. Дальше страницы открываются тремя способами:

1. **`catalog.getSection(section_id)`** — основной переход. Применим к id корневых разделов, id «показать всё» (§3.4), id из кнопок `open_section`, id из `default_section` (поиск, артист).
2. **`catalog.getAudio(url=...)`** — переход по прямой ссылке страницы. Понимает адреса разделов (`audios<UID>?section=X`, `audio?section=X`); в том числе ведёт на «скрытые» разделы вроде `in_progress`, кнопок на которые в витрине нет (их дают кнопки `open_url`).
3. **`catalog.replaceBlocks(replacement_ids)`** — переключение вкладок-подразделов внутри секции (§3.5).

Одна страница может иметь несколько адресов-псевдонимов: `vk.com`↔`vk.ru`,
`audios<UID>?section=X`↔`audio?section=X`, `section_id` и `url`. Все эти варианты
обозначают одну секцию.

### 3.4. «Показать всё» и собственные страницы блоков

У разворачиваемых блоков есть `meta.show_all_info = { "section_id", "title" }` — адрес страницы блока (например, карусель «Мои треки» на «Моей музыке» разворачивается в полный список на своей странице). Открывается через `getSection`. Собственная страница отдаёт тот же контент в списочных раскладках (`large_slider` → `list`).

Но `show_all_info.section_id` часто указывает на секцию, которой блок сам принадлежит: это значит «блок уже развёрнут», а не «есть куда перейти». Такие переходы нужно отбрасывать, иначе страница ссылается сама на себя. Подробности и счётчики — RESPONSE.md §6.1.

### 3.5. Вкладки подразделов

Блок с раскладкой `subsection_tabs` содержит кнопку `podcasts_subsection_tabs` со списком `options[]`: `{ "replacement_id": "#<section_id>/#<subsection_id>", "text": "Подкасты", "selected": 1 }`. Вкладка с `selected: 1` активна, её контент уже на странице, запрос за ней не нужен. Остальные вкладки — вызов `catalog.replaceBlocks` с токеном вкладки: в ответе блоки `from_block_ids` заменяются на `to_blocks`, порядок страницы сохраняется. Курсор пагинации страницы обновляется из `new_next_from`.

### 3.6. Пагинация (два уровня, курсоры opaque)

- Страница секции: `section.next_from` → `getSection(section_id, start_from=<курсор>)`.
  Пагинация продолжается, пока присутствует `next_from`.
- Ряд блока: `block.next_from` → `getBlockItems(block_id, start_from=<курсор>)` — следующая порция элементов блока.

Размер порции определяется VK и может меняться; для продолжения выдачи
используется `next_from`.

> Курсор `start_from` — opaque-строка для большинства разделов, но не для всех. В разделе «Недавнее» (`?section=recent`) VK присылает `start_from` в виде base64 JSON с состоянием раздела (имя блока, количество загруженных элементов, раскладка, токены блоков и позицию). Клиент должен передавать такой курсור серверу как есть, не пытаясь распарсить или синтезировать.

### 3.7. Эфемерные идентификаторы и ошибка 104

`section.id`, `block.id`, `default_section` и replacement-токены — opaque-строки.
Их нельзя синтезировать; при повторном запросе значения передаются серверу без
изменений. В текущем наборе `catalog.getBlockItems` завершился `104` в 4 из 530
захватов. При устаревшем или невалидном `block_id` актуальный ID получают из
повторно загруженной родительской страницы. `104` в выборке не означает, что
любой такой сбой обязательно вызван истечением.

### 3.8. Ленивое наполнение блоков

Содержимое блоков может быть частичным:
- **`audio_books` в текущих секционных ответах имеет непустые `audio_book_ids`**: наблюдались 125 уникальных пар `(section.id, block.id)`. Rust-модель пока не декодирует эти ID и пакет книг; `getBlockItems` нужен для продолжения по `next_from`, а не как обязательный способ получить первые ID;
- баннерные и смешанные блоки могут содержать пустые `*_ids` при наличии
  `next_from`; наличие курсора указывает на доступность продолжения;
- блок `action` не содержит сущностей: это кнопки/навигация.

### 3.9. Пустые секции — норма

Персональные подборки без подписок («Артисты и кураторы» и раздел «Вы начали
слушать») и медиатеки закрытых/удалённых пользователей (`Музыка <имя>`,
`<deleted-profile>`) возвращают секцию без блоков и пакетов. Такие ответы
отображаются как пустое состояние; отсутствие блоков не является ошибкой разбора.

### 3.10. Совместимость с изменениями API

VK добавляет типы блоков, раскладки и поля без предупреждения. Например,
`market_items` и связанные раскладки были в предыдущей выборке, но не встретились
в текущей; это не доказывает, что сервер удалил их из API. Парсер должен:
- сохранять неизвестные поля как есть (пригодятся при повторной сериализации/кэшировании);
- не падать на неизвестном `data_type` или `layout.name` — рисовать универсально (заголовок + список) и логировать.

## 4. Справочник методов

### 4.1. Навигация и витрина (`catalog.*`)

Параметры `need_blocks` и `extended` не взаимозаменяемы автоматически: что именно отправляет MusiMuX и что записано в текущем манифесте, показано в §2.6. Ответы описаны в §3.

#### `catalog.getAudio`

Корневой каталог или страница раздела по прямой ссылке. Точка входа в витрину.

| Параметр | Тип | Обязателен | Описание |
|---|---|---|---|
| `extended` | int | нет | В Rust-клиенте MusiMuX отправляется как `1` |
| `url` | string | нет | Прямая ссылка на раздел; без неё вызов возвращает корневой каталог |
| `owner_id` | int | нет | Наблюдался в отдельных захватах; текущий метод Rust-клиента его не добавляет |

Без `url` обычный вызов без владельца возвращал каталог из шести указателей
`catalog.sections`; запрос с `owner_id` в снимках мог вернуть один указатель.
С `url` корневой `catalog` сохраняется, а состав секций/блоков и пакетов зависит
от конкретного адреса. Прямой URL `section=general` может быть только указателем;
подробная страница загружается через `catalog.getSection` с `default_section`.
Наблюдения отдельных web/batch-вызовов не являются параметрами текущего клиента
и не задают фиксированное число generated-плейлистов.

#### `catalog.getSection`

Детальная загрузка секции с блоками — основной рабочий метод навигации.

| Параметр | Тип | Обязателен | Описание |
|---|---|---|---|
| `section_id` | string | да | Opaque-идентификатор секции |
| `need_blocks` | int | нет | В текущем Rust-клиенте всегда `1` |
| `extended` | int | нет | В текущем Rust-клиенте всегда `1` |
| `start_from` | string | нет | Курсор страницы из `section.next_from` |

Ответ: конверт `section` + пакеты секции. Пагинация — §3.6, истечение токенов — §3.7.

**Ошибки:** `8` (не та версия), `104` (секция не найдена или токен протух — §3.7).

#### `catalog.getBlockItems`

Продолжение блока загружается с помощью `next_from`, если он присутствует; для `audio_books` текущий набор уже содержит `audio_book_ids` (§3.8).

| Параметр | Тип | Обязателен | Описание |
|---|---|---|---|
| `block_id` | string | да | `block.id` |
| `extended` | int | нет | `1` — расширенная выдача |
| `start_from` | string | нет | Курсор из `block.next_from` |

Ответ: конверт `block` + пакеты элементов блока.

**Ошибки:** `104` на протухшем `block_id` — перевыгрузить страницу.

#### `catalog.replaceBlocks`

Переключение вкладок-подразделов секции (§3.5).

| Параметр | Тип | Обязателен | Описание |
|---|---|---|---|
| `replacement_ids` | string | да | Токены замены через запятую (по приложению; на практике один — вида `#<section_id>/#<subsection_id>`) из `actions[].options[].replacement_id` |

Ответ: `replacements { new_next_from, replacements[{ from_block_ids, to_blocks }] }` + пакеты новых блоков.

В текущем наборе манифестов `catalog.replaceBlocks` записан с `replacement_ids`.
Метод доступен в инструментах захвата; обычный экранный Rust-клиент его не вызывает.

**Известное ограничение приложения:** замены блоков на месте не выполняются — вкладки подразделов открываются переходами в секцию-подраздел (`catalog.getSection` по её id, страница кэшируется). Метод описан для полноты картины.

#### `catalog.getAudioSearch`

Подсказки поиска и поисковая витрина.

| Параметр | Тип | Обязателен | Описание |
|---|---|---|---|
| `query` | string | нет | Поисковая строка. **Именно `query`**, не `q` |
| `extended` | int | нет | Rust-клиент всегда отправляет `1` |
| `need_blocks` | int | нет | Rust-клиент отправляет `1` в пустом поиске и в запросе живых подсказок (`show_suggests=1`) |
| `show_suggests` | int | нет | Подсказки по мере ввода: Rust-клиент отправляет `1` вместе с `query` и `need_blocks=1` (в текущем наборе манифестов `.raw/search/` не записан) |
| `requested_section_id` | string | нет | Подраздел выдачи (по приложению) |

Без запроса текущий ответ содержит секцию с блоком `search_suggestions`, корневой
массив `suggestions` и пустой `albums`; один снимок содержит 20 элементов
подсказок. С `query`, `need_blocks=1` и `show_suggests=1` метод отдаёт подсказки
для введённого префикса в том же формате (блок `search_suggestions` основной
секции и корневой пакет `suggestions`). С запросом без `show_suggests` `catalog`
включает `default_section`, `pinned_section` и массив указателей `sections`;
содержимое выдачи открывается через `getSection`. `context` из подсказки можно
передать в следующий `catalog.getAudioSearch`. Число подсказок и указателей может
меняться.

**Особенность параметра:** поисковая строка передаётся в `query`. На `q` метод отвечает не ошибкой, а секцией подсказок — как будто запроса не было; выдача при этом молча теряется.

#### `catalog.getAudioArtist`

### 4.2. Медиатека и поиск аудио (`audio.*`)

#### `audio.get`

Список аудиозаписей пользователя или сообщества.

| Параметр | Тип | Обязателен | Описание |
|---|---|---|---|
| `owner_id` | int | нет | `>0` пользователь, `<0` сообщество; по умолчанию — текущий профиль |
| `count` | int | нет | 1–200 (по умолчанию 20) |
| `offset` | int | нет | Смещение |
| `album_id` | int | нет | Альбом/плейлист |
| `extended` | int | нет | `1` — полные метаданные и профили |

Ответ текущих успешных снимков: `{ "count": int, "items": [Audio], "groups": [...], "profiles": [...] }`; `next_from` в `audio.get` не наблюдался.
Пагинация выполняется с помощью параметра `offset`. Rust-обёртка разбирает
`count`/`items`; `groups` и `profiles` этим типом не сохраняются.

#### `audio.getById`

Метаданные и свежие прямые ссылки на поток по списку треков.

| Параметр | Тип | Обязателен | Описание |
|---|---|---|---|
| `audios` | string | да | `owner_id_audio_id` через запятую; для чужих/приватных — `owner_id_audio_id_accesskey` |

Ответ: массив `[Audio]`.

Особенности:
- принимает только числовые идентификаторы — иначе `100 (not integer)`;
- треки с `url: ""` (ограничение `content_restricted`) при повторном запросе пачкой часто получают рабочую ссылку;
- пачка обрабатывается целиком: один некорректный ID завершает вызов ошибкой,
  поэтому запрос рекомендуется разбивать на более мелкие пачки;
- эпизоды подкастов и аудиокниги методом не обслуживаются.

**Ошибки:** `100` (формат), `104` (не найдено).

#### `audio.getCount`

Число аудиозаписей медиатеки. Параметр: `owner_id` (обязателен). Ответ: целое число.

#### `audio.getPlaylists`

Плейлисты и альбомы владельца: `owner_id` (обязателен), `count` (1–200), `offset`, опционально `filters` (`"owned"` — только свои плейлисты владельца, без добавленных чужих альбомов). Ответ текущих захватов: `{ "count": int, "items": [Playlist], "profiles": [...], "groups": [...], "next_from": "..." }`; Rust-декодер хранит элементы как `AudioAlbum`. `AudioPlaylistPage` сохраняет только `count` и `items`; текущая обёртка продолжает через `offset` и не сохраняет `next_from`.

#### `audio.getPlaylistById`

Плейлист целиком через аудио-API: `owner_id`, `playlist_id` (обязательные),
`access_key` (опционален), `extended=1` (добавляет Rust-клиент). В одном
манифесте также встречался `audio_count`, но текущий Rust-метод его не отправляет.
Ответ — объект плейлиста с метаданными, включая `genres`, `is_following`,
`play_button`; поля обложки могут различаться (`photo`/`thumbs`). Rust возвращает
его как `AudioAlbum`, который сохраняет только часть wire-полей (см. §8.2 в
[`RESPONSE.md`](./RESPONSE.md)).

#### `audio.getLyrics`

Текст песни: `audio_id` в формате `owner_id_audio_id` (обязателен). Все шесть
успешных текущих снимков содержали `lyrics.timestamps` и не содержали `lyrics.text`;
код Rust также умеет разобрать `text` для совместимости с иной/старой формой.
Если текста нет, наблюдалась ошибка `104` — приложение трактует её как пустое
состояние, а не как сбой сети.

#### `audio.getPopular`

Чарт популярного: `count`, `offset`, `only_eng` (`1` — только зарубежное).
Комментарий текущего Rust-метода указывает диапазон `count` 1–1000; фактический
лимит может определяться сервером. Ответ — массив `[Audio]`.

#### `audio.getRecommendations`

Персональные рекомендации или похожие треки: `count`, `offset` (Rust-клиент
отправляет оба), `target_audio` (`owner_id_audio_id` — источник похожести; без
него — общая лента). В обоих успешных текущих снимках ответ имел только
`{ "count": int, "items": [Audio] }`; корневое поле `audios` не наблюдалось.

#### `audio.search`

Поиск по аудиобазе: `q` (обязателен), `count` (1–300), `offset`, `sort` (`0` релевантность, `1` дата добавления, `2` длительность), `extended`, `search_own` (`1` — только свои). Ответ: `{ "count": int, "items": [Audio] }`. Рекомендуемый вход в витрину поиска — `catalog.getAudioSearch` (§4.1), классический метод нужен для плоской выдачи треков.

#### `audio.getStreamMixSettings` и `audio.getStreamMixAudios`

Персональный бесконечный поток («Микс»):

| Метод | Параметры | Ответ |
|---|---|---|
| `audio.getStreamMixSettings` | `mix_id` (`common`, `my_music` или id из пакета `audio_stream_mixes`) | `{ "settings": { "title": "...", "mix_categories": [...] } }`; для части миксов возвращается пустой массив `[]`; допустимы обе формы |
| `audio.getStreamMixAudios` | `mix_id`, `append` (номер порции), `count`; код также поддерживает `options` (JSON) и `entity_id`, но эти два поля в текущем наборе не наблюдались | Массив `[Audio]` |

#### `audio.getRestrictionPopup`

Объяснение недоступности трека (регион, подписка): `audio_id` (`owner_id_id`). Ответ: `{ "title": "...", "icons": [{ "url", "width", "height" }] }` либо пустая структура.

#### `audio.getUploadServer`

Сервер загрузки собственного MP3. Без параметров. Ответ:
`{ "upload_url": "<temporary-upload-url>" }`. Адрес одноразовый; для каждой
загрузки требуется новый URL.

- дизлайки принимают `audio_ids` (список); методов `audio.addLike`/`removeLike` не существует (`3`);
- у `followArtist`/`unfollowArtist` обязателен `ref` (например, `ref=audio_player`); каталожный аналог — кнопка `toggle_artist_subscription`;
- `followPlaylist` работает лишь с `id >= 0`: автоподборки каталога (отрицательный id) не подписываются; ответ — запись плейлиста в медиатеке (`{ owner_id, playlist_id }`), у части токенов вместо объекта приходит «готово» — пару id тогда даёт `audio.getPlaylistById` (поле `followed`);
- отдельного `unfollowPlaylist` нет: подписка снимается `audio.deletePlaylist` по паре из `followed` — удаляется запись медиатеки, сам плейлист остаётся у владельца;
- `savePlaylistAsCopy` доступен, когда в `permissions` плейлиста `save_as_copy = true` (у автоподборок каталога с отрицательным id), копия появляется в своих плейлистах;
- `actions` у `reorderInPlaylist` — JSON-массив троек `[owner_id, audio_id, new_index]`, по одной на перемещённый трек: `new_index` — позиция в плейлисте после перемещения (с нуля);
- загрузка обложки состоит из трёх шагов: `photos.getAudioPlaylistCoverUploadServer` → multipart-загрузка с полем `photo` → `audio.setPlaylistCoverPhoto` с полученными `photo` и `hash`; убрать обложку — `audio.deletePlaylistCoverPhoto`.

## 6. Подводные камни (сводка)

- Rust-клиент по умолчанию использует `v=8.154` и мобильные заголовки; некоторые вспомогательные вызовы явно переопределяют `v` (`5.143` для обложек, `5.272` как fallback дизлайка) (§2, §4.7–4.8).
- Каталог читается «скелет + пакеты»: склейка по `*_ids` в порядке VK (§3.1).
- Идентификаторы секций/блоков/замен — opaque-строки, хранить и возвращать как есть; протухают — `104` и перевыгрузка (§3.7).
- В текущих снимках `audio_books` блоки содержат ID; Rust-модель пока не разрешает их в элементы. `getBlockItems` используется для продолжения по `next_from`, не обязательно для начальной выдачи (§3.8).
- Пустые секции и пустой `[]` у `getStreamMixSettings` — валидные ответы, а не поломки (§3.9, §4.2).
- `podcast_episodes` присутствовал в предыдущей выборке, но не наблюдался в текущей; доступность эпизодного потока сейчас не подтверждена. `audio.getById` обслуживает только обычные аудиозаписи (§4.3, `RESPONSE.md` §8.6).
- В текущих успешных снимках `audio.getRecommendations` есть `items`; корневое `audios` не наблюдалось (§4.2).
- Страницы псевдонимов (`vk.com`↔`vk.ru`, `audios<UID>`↔`audio?section=`) — одна и та же секция (§3.3).
- Неизвестные типы/поля — сохранять и не падать (§3.10).
